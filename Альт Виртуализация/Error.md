### Error Connection error 401: permission denied - invalid PVE ticket

<img width="1375" height="273" alt="image" src="https://github.com/user-attachments/assets/fcfabf0a-1273-435a-9708-62622624a2cb" />

Эта ошибка означает, что истек срок действия или является недействительным тикет авторизации (сессия) в системе виртуализации Proxmox Virtual Environment (PVE).

Чаще всего это происходит при использовании API, консольных утилит (например, pvesh), резервного копирования (Proxmox Backup Server), плагинов для Grafana/Whmcs или при долго открытом веб-интерфейсе.

Вот пошаговое руководство, как это исправить:

Выполните следующие действия для решения проблемы:

Шаг 1. Полная очистка сессии в браузере (Самое важное)<br>
Пока вы не удалите старые куки, ошибка не уйдет.Закройте текущую вкладку с Proxmox.<br>
Откройте новое окно в режиме Инкогнито (Ctrl + Shift + N или Ctrl + Shift + P).<br>
Попробуйте зайти по адресу https://ваша-нода:8006.<br>
Альтернатива:<br> 
В обычном окне нажмите F12 -> вкладка Application (или Хранилище) -> Cookies -> нажмите правой кнопкой на адрес сервера и выберите Clear (Очистить).<br> 
После этого обновите страницу (Ctrl + F5).<br>
Шаг 2. Проверка и очистка старых тикетов на сервере<br>
Иногда повреждается сам файл ключей аутентификации, из которого генерируются тикеты.<br> 
Проверьте, что системное время создания ключей не забаговалось.<br>
Выполните команду:
```bash
ls -l /etc/pve/authkey.pub
```
Если размер файла равен 0 или дата выглядит некорректной, система не может проверить тикеты. <br>
Если с файлом всё в порядке, просто обновите конфигурацию кластера:
```bash
pvecm updatecerts --force
```
Шаг 3. Завершение зависших сессий пользователя rootЕсли вы заходите под root, старые сессии могли зависнуть в corosync/pmxcfs.<br> 
Перезапустите зависимую службу прокси еще раз, но строго после того, как закроете все вкладки в браузере:
```bash
systemctl restart pveproxy
```
Прочие причины.

Проверка рассинхронизации времени (Самая частая причина)Тикет PVE жестко привязан ко времени создания. 

Если время на сервере Proxmox и на клиенте (или на бэкап-сервере PBS) отличается хотя бы на пару минут, сервер будет считать тикет «просроченным» или «пришедшим из будущего» и выдаст 401: permission denied.Как проверить: Выполните команду date на сервере.Решение: Настройте и синхронизируйте службу точного времени NTP:bashsystemctl restart chrony
или, если используется systemd-timesyncd:
```bash
timedatectl set-ntp true
```
Если ошибка возникает в Терминале (SSH / CLI)

Если вы выполняете команды автоматизации или скрипты, вам нужно обновить тикет авторизации.

Решение: Перезапустите службу управления PVE. Это сбросит зависшие сессии и заставит систему принимать новые тикеты:
```bash
systemctl restart pveproxy.service
systemctl restart pvedaemon.service
```
Проверьте статус файловой системы кластера (pve-cluster)

Proxmox хранит конфигурацию и авторизационные ключи в специальной распределенной файловой системе /etc/pve/, которая зависит от службы pve-cluster. 

Если она зависла, авторизация ломается.
```bash
systemctl status pve-cluster.service
```
Если статус службы failed или она «зависла», принудительно перезапустите её:
```bash
systemctl restart pve-cluster.service
```
